# v1.8.2 跨模块修复与兼容说明

本版修复行动权利范围与渠道映射不一致、消费者沟通漏查证据父链两类问题。沿用同一案件台账，不自动修改记录，也不增加外发权限。

## 行动权利与渠道映射

`channel_check.py` 和 `submission_dependencies.py` 共用 `review_right_scope()`。只运行提交前审查时，也会检查范围，不依赖调用者先运行渠道脚本。

行动显式填写 `right_ids` 时，列表必须非空、无重复，且每个 ID 都存在于本案。渠道 `work_mappings` 的每个 `right_id` 必须在该列表中，`target_id` 必须属于行动目标。权利、渠道记录及映射明确填写其他案件或品牌标签时会报错。

例如，行动声明使用 `r1`，渠道映射使用 `r2`，即使两者都是本品牌版权，也不能通过检查。工具不会自动把 `r2` 加入行动，也不会悄悄忽略它的材料。应核对真实主张和授权，修正记录后重新审查。

省略 `right_ids` 的旧记录仍按本案全部权利处理。显式 `[]`、`null`、重复值和不存在的 ID 不等于省略。未被选中且与当前主张无关的材料不会因此被读取。

范围冲突时，渠道状态为 `needs_review`。审批依赖返回 `complete: false` 和 `sha256: null`，不产生可匹配的材料指纹。范围正确时，所选权利的材料继续读取实际文件；缺失文件、字节变化或哈希不符会阻塞审批。

提交前材料快照版本保持 `1.1`。材料指纹匹配、渠道清单通过和取得真实发送授权是三项不同检查，不能互相替代。

## 消费者证据父链

消费者配置、官方渠道和引用证据使用共享身份检查。显式 `case_id`、`brand_id` 必须与当前案件一致。证据省略旧版可选标签时，不据此认定归属已经核实。

从每个渠道的 `evidence_ids` 出发，沿 `derived_from_id` 检查全部祖先。父记录缺失、重复、循环或身份冲突时停止生成。副本自己的品牌标签不能掩盖父记录冲突。所有渠道合计最多引用 1,000 个证据节点，共用父记录只计一次。

草稿指纹包含全部被引用证据及父记录。父记录哈希、来源、身份或关联改变后，旧复核失效。与这些渠道无关、未被引用的证据记录不进入指纹。内部证据字段不写入消费者文本或公开链接。

消费者输出新增 `snapshot_version: 1.1`。旧版消费者复核需要重新核对实际官方渠道、来源和草稿，再记录新审批。审批 JSON 的 `version: 1.0` 保持不变。工具不会替换旧哈希，也不迁移私有案件。

**消费者指纹绑定台账记录，不重新读取证据原文件。** 若原文件发生变化而台账没有同步，单靠这个草稿工具不能发现。公开使用前仍需独立核验证据原件和当前渠道。权利通知的文件完整性核对由提交前审查处理，不代表消费者工具已经做了同样检查。

所有消费者输出继续保留草稿标识，`authorizes_publication` 和 `sends_messages` 均为 `false`。存在错误时，命令行返回非零退出码，不留下新的草稿目录。

## 回归与升级

在仓库根目录执行：

```bash
python3 -B -m unittest discover -s tests -v
python3 -B tests/extended_v18_probes.py
```

`test_v181_residual_regressions.py` 保存 10 项追加审计验收；`test_v182_contracts.py` 补充 34 项组合检查。测试使用完整生产模块和合成数据，不调用真实投诉服务。

升级时替换完整 Skill 目录，先备份旧目录并移出宿主扫描路径。不要覆盖私有案件，不要把新旧脚本放在同一安装目录。安装与回滚以 Release 附件 `INSTALL.md` 为准。
