# 消费者沟通草稿

本工具生成三份中文草稿：官方入口说明、客服线索核对话术和线索提交说明。内容只使用本案已记录并复核的官方渠道，不加入被诉站点、内部授权或证书正文。

工具不联网、不发送消息，也不发布公告。所有输出都保留草稿标识，即使已记录的复核与当前版本一致，也不能直接外发。

## 使用方法

先把官方入口和核验依据记入同一案件，再指定仓库外的私有输出目录。

```bash
python3 scripts/consumer_materials.py \
  --case /path/to/private-case/case-record.json \
  --output-root /path/to/private-drafts
```

输出目录须已经存在。每次运行新建 `consumer-drafts-` 目录，不覆盖旧草稿。工具不修改案件。

## 官方渠道记录

案件需填写 `case_id`、`brand_id`、纯文本 `brand` 和 `official_domains`。官方域名必须显式记录，使用小写 ASCII 或 Punycode。工具不会从前一案件继承品牌，也不自动猜测子域名。

在本案加入可选的 `consumer_communications`，格式如下。示例时间和核验状态需要按实际工作填写。

```json
{
  "version": "1.0",
  "brand_id": "本案品牌 ID",
  "verified_by": "实际复核者",
  "verification_source": "核验依据的私有引用",
  "checked_at": "2026-11-13T03:00:00Z",
  "review_before": "2026-11-13T05:00:00Z",
  "support_channel_id": "support-1",
  "channels": [
    {
      "id": "support-1",
      "kind": "support",
      "url": "https://brand.example/support",
      "verification_status": "unknown",
      "verified_at": "2026-11-13T02:00:00Z",
      "evidence_ids": ["evidence-1"]
    }
  ]
}
```

示例使用 `unknown`，不能直接通过检查。实际完成核验后，再改为 `verified`。每个渠道都须引用同案证据。配置、渠道、证据及其派生父记录明确标记其他案件或品牌时会报错。

渠道类型只接受 `website`、`store` 和 `support`，每案可记录 1 至 30 个。至少要有一个已核实的客服入口。URL 须使用 HTTPS，主机与 `official_domains` 中的域名完全相同，不能包含凭据、查询参数或片段。

该限制意味着有查询参数的店铺链接、邮件地址和其他社交联系方式暂不支持。不要为了通过检查而删除链接中有业务意义的参数或伪造官方域名。

`checked_at` 是本次渠道复核时间，`review_before` 是内部再次复核时间。时间过期、渠道记录晚于整体复核、证据缺失或重复渠道时，工具会停止生成。

## 输出与复核

工具输出以下文件：

| 文件 | 用途 |
|---|---|
| `official-channels.txt` | 列出本次核验的官方入口，提醒核对完整域名。未列出的渠道仍需另查，不直接认定为假冒。 |
| `customer-reply.txt` | 请求页面地址、时间和问题说明，避免索取密码、验证码或完整支付资料。 |
| `report-intake.txt` | 说明最小线索范围和已核实的客服入口，避免公开披露消费者资料或未核实指控。 |
| `internal-review.json` | 保存材料快照、文件哈希和复核状态。此文件留在私有目录，不对外发送。 |

三份草稿都不保证退款、赔偿或第三方处理结果。需要调整语种、补充具体业务事实或发布对象时，应由有权限的人另行复核。本版不自动翻译、不建立第三方黑名单。

首次生成时，状态为 `draft_needs_review`。把[空白复核模板](../assets/consumer-approval.json)复制到私有目录，完成实际复核后，再填写案件、品牌、快照哈希、复核者、授权来源和有效时间。三项检查默认均为 `false`。

重新运行时增加 `--approval /path/to/private-case/consumer-approval.json`。工具会核对官方渠道、来源记录、模板与实际草稿字节。品牌、渠道、依据或模板变化后，旧复核不再匹配。传入无效复核时，工具不会留下新草稿。

从 v1.8.2 起，来源指纹还包含沿 `derived_from_id` 找到的全部父记录。父记录缺失、循环或冲突时停止；父记录变化会使旧复核失效。消费者指纹版本为 `1.1`，旧复核需要重新检查并记录，详见[跨模块修复说明](residual-fixes.md)。

## 验证边界

`review_matches_draft` 只表示记录与当前材料一致。工具不认证复核者身份，不独立验证网站归属，也不授予发布权限。记录中的 `verified` 不能代替实际核验。

消费者指纹核对台账中的证据记录及父链，不重新读取证据原文件。原文件变化而台账未同步时，本工具不能据此发现变化。公开使用前仍需独立核验来源文件。

**输出始终是待人工处理的草稿。** 公开使用前仍需核实最新渠道、文本、隐私和发布授权。内部快照、回执及案件资料不得一起公开。

退出码 `0` 表示草稿已保存并回读核对，`1` 表示输入、复核或写入失败。成功生成不等于通过公开发布审批。部分写入失败时，只清理本次目录，不改动案件和既有草稿。
