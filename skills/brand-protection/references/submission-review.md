# 提交前审查

本工具核对已记录的审批与当前材料。快照包含正文、附件、接收方、目标、权利、费用和授权范围。材料变化后，旧审批不再匹配。

工具只读，不创建审批、不认证审批人身份，也不发送材料。输出始终保留 `authorizes_submission: false`。

## 准备材料

沿用同一案件的 `actions`、`targets`、`providers`、`evidence`、`rights` 和 `parties`。行动需记录目标、接收方角色、渠道、依据、请求措施、授权来源、签署权限和主张证据。

权利的 `brand_id` 必须与本案一致，`holder_party_id` 必须引用本案主体。主张证据与附件必须有可读取的本地文件和 SHA-256。只记录远端 URL、没有保全文件的证据，还不能通过此检查。

在待审行动中增加 `preflight_payload`。不要改写已提交版本或历史回执。

```json
{
  "version": "1.0",
  "operation": "initial_notice",
  "recipient": "已核实的具体接收方或入口",
  "dedupe_key": "本案本次行动的稳定键",
  "body": {
    "path": "相对于私有材料目录的正文文件",
    "sha256": "待填写的 64 位小写 SHA-256"
  },
  "attachment_ids": ["evidence-1"],
  "fees": {"amount": "0.00", "currency": "USD"}
}
```

操作可用 `initial_notice`、`remind`、`resubmit`、`send_supplement`、`send_escalation` 和 `send_correction`。更正必须使用独立的关联行动。正文使用 UTF-8，空正文和未填写的模板标记会阻止检查。

费用需要明确数额和币种；免费也填写零。该字段只绑定审查范围，不授予付款权限。当前工具一次检查一个接收方；新增抄送等未知字段会报错。

## 取得快照并审查

先不传审批文件，查看材料快照和缺口：

```bash
python3 scripts/submission_review.py \
  --case /path/to/private-case/case-record.json \
  --action-id action-1 \
  --source-root /path/to/private-materials
```

缺少审批时返回非零退出码，并在材料有效时给出 `snapshot.sha256`。这一步不会生成批准。

把[空白审批模板](../assets/submission-approval.json)复制到私有目录。实际复核完成后，再填写案件、行动、快照哈希、复核者、授权来源和有效时间。七项检查分别覆盖权利、相反证据、接收方、披露、签署权限、费用及最新反馈。默认值均为 `false`。

审批必须由有相应权限的人确认。适用规则要求专业判断时，记录专业复核结果。不能把填满字段当作事实、授权或法律结论已被验证。

复核后重新运行，并增加 `--approval /path/to/private-case/submission-approval.json`。工具重新读取文件，不沿用上次内存结果。

## 变更与阻塞

正文或附件字节变化、目标变化、权利材料变化、接收方变化、费用变化、相反证据变化或案件授权变化，都会导致快照不匹配。审批过期或尚未生效时也会阻塞。

行动被冻结、已经终结、关联工作仍在进行、同组送达不明或同键已经发送时，已有审批不能解除阻塞。渠道明确的外发限制仍需满足。更正与原行动共用未决送达阻断，但不继承原行动的批准。

状态从待审改为已授权，不会单独改变材料快照。新材料通过复核后应形成新的审批记录，保留旧记录供审计，不覆盖已发送历史。

## 结果与执行边界

`approval_matches_snapshot` 表示记录中的审批与本次读取的材料一致。它不表示已经核实真实审批人，也不表示当前可以发送。退出码 `0` 只表示本工具的检查通过，`1` 表示需要处理缺口。

本工具不完成队列的全部调度判断，不读取实时邮箱，不取得排他锁。实际外发前，仍须读取最新反馈、核验用户当前指令、运行[队列检查](queue-safety.md)，并按[持续跟进规则](follow-up.md)保存发送状态。

文件在检查结束后仍可能变化。发送器必须重新核对实际使用的字节和批准范围。本版没有发送器，也不提供原子执行保证。
