# v1.9.0 审计修复与宿主衔接

本版按仓库所有者要求统一修复 v1.8.3 审计发现，并补齐相关建议。包内只有通用 Skill、空白模板及辅助脚本。合成测试留在源码仓库，真实品牌、案件、证据和凭据保存在仓库之外。

## 修复的问题

| 编号 | 修复 |
|---|---|
| F01 | 入选材料引用的来源纳入提交审批快照。读取范围、披露限制或来源身份变化后，旧审批失效；缺失、重复或跨案引用阻断核验 |
| F02 | 有当前具体行为证据时，优先复核证据，同时保留注册待核信息；注册未知不再覆盖已有线索 |
| F03 | macOS 系统别名测试使用受控的目录，不再假定用户 TMPDIR 位于 /private/var |
| O01 | 持续观察独立于原处置终态；明确启用但缺少复查任务时报告覆盖缺口，暂停或结束后不自动启用 |
| S01 | 单次 HTTPS 的连接、发送、状态行、响应头、分块解析及正文共用截止时间，阻断持续慢滴响应 |

## 补充的能力

只读队列增加 `--validate-only`，可检查未启用和暂停案件的结构及历史关联。调查阶段的有效目标级任务可覆盖下一步，健康运行不再误报期限冲突。JSON 输入和案件结构采用共同预算；预算错误不授予执行权限，可独立解析的期限警报保留。

RDAP 增加显式 `--archive-root`，保全原始响应、哈希及可读路径。默认仍只读。网页取证 CLI 增加 `--total-timeout`，默认 30 秒，最大 120 秒。父进程限制只采集子进程的总时间，覆盖 DNS 和全部跳转；成功回传后才保存证据。最终文件写入不计入采集预算。

可选文件宿主适配器提供 OS 互斥、修订号比较、原子写回、反馈分页及范围检查。消息处理状态和游标同次提交；送达核清后仍保留尝试及其关联，不能靠删除历史解除去重。暂停与恢复须显式操作。健康周期依据真实运行及读取时间，补写旧记录不会刷新数据时效。连接器和独立观察者仍须另行验收；适配器不连接邮箱、不发送、不配置调度器。

补充权利材料不足、送达不明、结案后更正和复发观察的合成场景。法律参考增加 URS 缺席答辩和加拿大海关窗口，分别说明触发事件与延期条件；实际通知和现行程序优先，不硬编码普适法律期限。

## 升级与安装

从本版 Release 下载 ZIP、`INSTALL.md`、`PACKAGE-MANIFEST.json`、`VALIDATION.json`、`RELEASE-NOTES.md` 和 `SHA256SUMS.txt`。按系统核对全部摘要后，将旧安装移到宿主扫描路径之外，再安装完整 `brand-protection/` 目录。安装步骤见随包附件及[安装文档](../installation.md)。

案件仍为 `schema_version: 1.3`，新增字段可选，工具不自动迁移旧案。提交审批快照升级为 `1.2`，所有旧审批均须重新核对，不能批量替换旧哈希。消费者草稿及证据导出的既有复核要求继续适用。

## 验证范围

保留既有回归、队列字段变异和跨模块检查。新增测试覆盖审计反例、来源依赖、观察生命周期、反馈分页、互斥、原子失败、采集截止时间、模板及发布来源证明。

原生 CI 继续使用八环境矩阵：Ubuntu 22.04 的 Python 3.9、3.11、3.13、3.14，以及 Ubuntu 24.04、Windows Server 2025、macOS 15 arm64 和 macOS 15 Intel 的 Python 3.13。实际执行结果见相同提交的 Actions，数量由发布构建生成。

构建验证固定提交的 Skill、版本配置、安装说明和发布说明，核对资产模板基线，并执行实际复制安装命令。包内脚本测试与公开接口探测通过后，上传草稿附件，重新下载校验再公开发布。原生命令和入口检查不证明每个宿主应用已实际加载。

本版不包含真实品牌或案件，不启动持续监测。真实连接器、自然调度、签署、外发、独立告警及法律结果仍须在明确授权的具体环境验收。
